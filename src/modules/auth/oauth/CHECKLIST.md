## 1. Архитектурные решения (зафиксировано 13.10.2026)

| Вопрос | Решение | Почему |
|---|---|---|
| Протокол | OAuth 2.0 Authorization Code + **PKCE (S256)** + `state`, всё на сервере | Секрет не уходит в браузер; PKCE и state закрывают подмену кода и CSRF на callback |
| Где обрабатывается | Два Route Handler: `app/(frontend)/auth/yandex/start/route.ts` и `.../callback/route.ts` | Нужен GET-редирект и выставление cookie; Server Action для внешнего редиректа не годится |
| Хранение state/PKCE | Redis, ключ по случайному id + httpOnly-cookie с этим id, TTL 10 мин, одноразово (GETDEL) | Как `pendingAuth` — клиент держит только непредсказуемый идентификатор |
| Токены Яндекса | **Не храним.** access_token используется один раз для `/info` и забывается; refresh_token не запрашиваем | Нечему утекать; нам не нужен доступ к Яндексу после входа |
| Запрашиваемые доступы | `login:email` + `login:info` (имя). Ничего больше | Минимизация ПД — и закон, и меньше текста в документах |
| Ключ связи | Яндекс `id` (стабильный), **не почта** | Почту в Яндексе можно сменить; по почте искать нельзя |
| Таблица | Новая коллекция `user-identities`: `provider`, `subject`, `user`, `emailAtLink`, `linkedAt`, `lastUsedAt`; уникальный индекс `(provider, subject)`, индекс по `user` | Провайдер-независимо; VK ID — новая строка, а не новая колонка |
| Совпадение почты с существующим аккаунтом | **Автосклейки нет никогда.** Привязка только после подтверждения владения аккаунтом: код на почту (OTP нового типа `link_oauth`) | Иначе контроль над Яндекс-аккаунтом с этой почтой = доступ к чужим заказам |
| Второй фактор | Вход через Яндекс = полноценный вход **без нашего OTP**; `twoFAVerified` НЕ трогаем (это аудит «подтверждали кодом»); доверенное устройство НЕ выдаём | Аутентификацию сделал Яндекс; доверенное устройство — артефакт именно нашего OTP-пути (см. `trustedDevice.ts`) |
| Уведомление о входе | Как у обычного входа: `login_new_device`, если устройство не встречалось | Сохраняем существующее поведение безопасности |
| Выдача JWT без пароля | Своя функция `issueSessionWithoutPassword` (раздел 7): `getFieldsToSign` + `jwtSign` (экспортированы из `payload`) + строка в `users_sessions` прямым SQL + ручное повторение проверок `beforeLogin` | `payload.login()` требует пароль, `addSessionToUser` в 3.85.1 наружу не экспортирован (проверено) |
| Новый пользователь | Создаётся со **случайным паролем 32 байта**, который никто не знает, и флагом `hasPassword: false` | Payload требует пароль на create; флаг нужен UI, удалению аккаунта и смене пароля |
| Согласия | Экран «Имя + согласия» после callback, **до** создания пользователя; запись в `user-consents` тем же кодом, что в `registerAction` | Акцепт оферты и согласие на ПД обязательны, Яндекс их не заменяет |
| Включение | Галочка «Настройки сайта → Вход через Яндекс ID» (`settings.yandexId.enabled`, по умолчанию выкл.) + ключи в env. Было: env-флаг `YANDEX_ID_ENABLED` — заменён 15.10.2026 по решению владельца | Кнопка и роуты мертвы, пока документы не обновлены; включает и выключает владелец без выкладки |
| One-tap виджет YaAuthSuggest | **Не в v1** | Сторонний скрипт → CSP `script-src`, документ о cookie, отдельное решение |

Поток:

```
[Кнопка «Войти с Яндекс ID»] → GET /auth/yandex/start?next=/cart
   └─ state+PKCE в Redis, cookie oauth-flow, 302 → oauth.yandex.ru/authorize
oauth.yandex.ru → 302 → GET /auth/yandex/callback?code&state
   ├─ state не совпал / истёк / error=access_denied → /auth/login?oauth_error=…
   ├─ code → token (POST oauth.yandex.ru/token, с code_verifier) → GET login.yandex.ru/info
   ├─ identity найдена          → проверка статуса → issueSession → completeLogin → next
   ├─ identity нет, email занят → pending «link» в Redis → /auth/yandex/link (код на почту)
   └─ identity нет, email новый → pending «register» в Redis → /auth/yandex/complete (имя + согласия)
```

акцепты остаются привязаны к своей версии).

  договор (Пользовательское соглашение);

- обработчик по поручению: ООО «ЯНДЕКС» (Метрика) — если в уведомлении раньше этого не было;
- без изменений: трансграничной передачи нет, БД в РФ (сверить адрес ЦОД с тем, что указан).
