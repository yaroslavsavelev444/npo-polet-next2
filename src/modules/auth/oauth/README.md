# Вход через Яндекс ID

Покупатель входит или регистрируется через свою учётную запись Яндекса — без
пароля и без кода из письма. План, принятые решения и статус —
[CHECKLIST.md](CHECKLIST.md); правки документов /consents —
[LEGAL_EDITS.md](LEGAL_EDITS.md); выкладка — `deploy/README.md`, раздел
«Вход через Яндекс ID».

## Как это выглядит для покупателя

| Ситуация | Что происходит |
|---|---|
| Яндекс уже привязан | Сразу вход, возврат туда, откуда начал (корзина, оформление) |
| Новый покупатель, почта на Яндексе (`@yandex.ru`, `@ya.ru`…) | Форма «имя + согласия» → аккаунт создан, вход |
| Новый покупатель, другая почта | Та же форма → код на почту → вход |
| Аккаунт с этой почтой уже есть | Код на почту аккаунта → привязка и вход. **Без кода привязки нет** |
| В Яндексе нет почты | Сообщение: добавить почту в Яндексе или зарегистрироваться по почте |
| Нажал «Отмена» на Яндексе | Возврат на страницу входа с предупреждением |

В кабинете («Безопасность → Способы входа»): привязать Яндекс ID к
существующему аккаунту, отвязать его, задать пароль. Отвязать последний способ
входа нельзя — у аккаунта без пароля сначала предлагается задать пароль.
Удаление аккаунта без пароля подтверждается кодом на почту.

## Как устроено

```
кнопка ─► /auth/yandex/start ─► oauth.yandex.ru ─► /auth/yandex/callback
             state + PKCE в Redis                     │  обмен кода, профиль
                                                      ▼
                                          resolve.ts — развилка
           ┌───────────────┬───────────────────┬──────────────────┐
         login          linked            link_required          signup
   issueSession →   (из кабинета)   код link_oauth → экран    форма «имя +
   completeLogin                     /auth/verify-otp →       согласия» →
                                     привязка в verifyOtp     аккаунт
```

| Файл | Что делает |
|---|---|
| `config.ts` | Флаг и ключи из окружения; `null` — фича выключена |
| `yandex.ts` | Адрес авторизации, обмен кода, профиль. Токен живёт одну функцию |
| `pkce.ts` | PKCE S256, случайные идентификаторы, сравнение state |
| `flowStore.ts` | Состояния потока и черновик регистрации в Redis |
| `resolve.ts` | Развилка: вход / привязка / код / регистрация / ошибка |
| `identities.ts` | Коллекция `user-identities`: поиск, привязка, отвязка |
| `issueSession.ts` | Выдача JWT без пароля (повторяет внутренности `payload.login`) |
| `confirmByCode.ts` | Путь через код на почту (экран `/auth/verify-otp`) |
| `actions.ts` | Форма регистрации, отвязка, «задать пароль» |
| `returnPath.ts` | Куда вернуть после входа (только свой сайт) |
| `components/` | Кнопка, ошибки, форма регистрации, «Способы входа» |

Маршруты — `app/(frontend)/auth/yandex/{start,callback,complete}`.

### Что важно не сломать

- **Совпадение почты не даёт входа.** Только код на почту аккаунта
  (`resolve.ts`). Это главная защита от захвата аккаунтов.
- **Ключ привязки — идентификатор Яндекса**, не почта: почту в Яндексе можно
  сменить.
- **Токены Яндекса не хранятся и не логируются** (`yandex.ts`).
- **`issueSession.ts` повторяет внутренности Payload.** При обновлении Payload
  перечитать `node_modules/payload/dist/auth/operations/login.js` и
  `sessions.js` и прогнать `pnpm test:oauth`.
- Cookie входа ставит только `lib/completeLogin.ts` — как и для обычного входа.

## Как проверить локально

Настоящий Яндекс не нужен — есть мок со страницей согласия, который честно
проверяет PKCE, Basic и одноразовость кода:

```
preview: mock-yandex            (node tests/e2e/mock-yandex.mjs, порт 4610)
preview: npo-polet-dev-yandex   (next dev с ключами и адресами мока)
```

Вход включается галочкой «Настройки сайта → Вход через Яндекс ID» в админке
(по умолчанию выключена). Мок слушает `127.0.0.1`, витрина — `localhost`:
для браузера это разные сайты, как oauth.yandex.ru и npo-polet.ru, поэтому
локально проверяется и возврат с чужого сайта (см. proxy.ts,
isCrossSitePageNavigation). С моком на `localhost` эта часть не видна.

На странице мока задаются id, почта и имя «аккаунта Яндекса» — так проходятся
все ветки таблицы выше. Код из письма при `EMAIL_ENABLED=false` достаётся из
базы перебором хеша (см. память проекта «OTP восстанавливается локально»).

Тесты: `pnpm test:oauth` — выдача сессии на настоящем Postgres, развилка,
гонка привязок, адрес возврата, PKCE по эталонному вектору RFC 7636.

## Как добавить VK ID или другой сервис

1. Значение в `OAuthProviderId` (`types.ts`) и в `options` поля `provider`
   коллекции `UserIdentities` (+ миграция enum).
2. Клиент по образцу `yandex.ts`, возвращающий `{ subject, email, name }`.
3. Свои `start`/`callback` или параметр провайдера в существующих; `resolve.ts`
   и всё после него уже не зависят от провайдера.
4. Документы /consents: новый источник данных.
