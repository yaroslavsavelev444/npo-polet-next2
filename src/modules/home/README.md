# Главная страница

Всё, что нужно знать, чтобы заменить временные материалы на реальные.

---

## 1. Куда класть файлы

| Что | Куда | Формат |
|---|---|---|
| Фоновое видео первого экрана | `public/videos/hero/` | `.webm` + `.mp4` + `poster.jpg` |
| Фотографии секций | `public/images/home/` | `.jpg` (или `.webp`) |
| Тексты, цифры, годы | `src/modules/home/content/home-content.ts` | — |
| Вопросы FAQ | админка → **Контент → FAQ** | — |
| Товары на главной | админка → товар → **Показывать на главной** | — |

Пути к медиа объявлены в одном файле — [`lib/media.ts`](./lib/media.ts). Компоненты
знают только ключи, поэтому переезд на CDN или в Payload — правка этого одного файла.

## 2. Hero-видео

### Требования к файлу

| Параметр | Значение | Почему так |
|---|---|---|
| Разрешение | **1920×1080** (десктоп), **1080×1350** или 720×1280 (мобильный) | Выше 1080p на фоне под затемнением не различить, а вес растёт вдвое |
| Кодек | **AV1** или **VP9** в `.webm` + **H.264 High** в `.mp4` | Safari и iOS не берут VP9/AV1 в webm — `.mp4` обязателен как запасной |
| Битрейт | **2.5–4 Мбит/с** для 1080p, **1–1.5** для мобильного | Фон под градиентом и в движении прощает сжатие |
| Длительность | **15–30 с**, бесшовная петля | Длиннее никто не досматривает, а вес линейно растёт |
| Звук | **удалить дорожку полностью** | Видео всё равно `muted`; дорожка — мёртвый вес |
| Частота кадров | 24–30 | 60 fps на фоне не читается, а вес удваивает |
| Размер | цель **< 6 МБ** десктоп, **< 2 МБ** мобильный | — |

### Команды для сжатия

Требуется `ffmpeg` (`brew install ffmpeg`).

Десктоп, `.mp4` (H.264 — запасной вариант, нужен Safari/iOS):

```bash
ffmpeg -i исходник.mov -vf "scale=1920:-2,fps=30" -an \
  -c:v libx264 -profile:v high -preset slow -crf 24 -pix_fmt yuv420p \
  -movflags +faststart public/videos/hero/hero.mp4
```

Десктоп, `.webm` (VP9 — основной, меньше вес при том же качестве):

```bash
ffmpeg -i исходник.mov -vf "scale=1920:-2,fps=30" -an \
  -c:v libvpx-vp9 -b:v 0 -crf 33 -row-mt 1 -deadline good -cpu-used 2 \
  public/videos/hero/hero.webm
```

Мобильный (короче и легче — на телефоне виден только центр кадра):

```bash
ffmpeg -i исходник.mov -vf "scale=-2:1280,crop=720:1280,fps=25" -an -t 15 \
  -c:v libx264 -profile:v high -preset slow -crf 27 -pix_fmt yuv420p \
  -movflags +faststart public/videos/hero/hero-mobile.mp4

ffmpeg -i исходник.mov -vf "scale=-2:1280,crop=720:1280,fps=25" -an -t 15 \
  -c:v libvpx-vp9 -b:v 0 -crf 36 -row-mt 1 -deadline good -cpu-used 2 \
  public/videos/hero/hero-mobile.webm
```

Постер — первый кадр ролика (**обязателен**: именно он, а не видео, является
LCP-элементом страницы):

```bash
ffmpeg -i public/videos/hero/hero.mp4 -vframes 1 -q:v 4 \
  public/videos/hero/poster.jpg
```

> `-movflags +faststart` переносит индекс в начало файла. Без него браузер
> вынужден скачать ролик целиком, прежде чем показать первый кадр.

### Включение

После того как файлы на месте — в [`lib/media.ts`](./lib/media.ts):

```ts
export const heroVideo: HeroVideoManifest = {
	available: true,   // ← было false
	...
};
```

### Как видео ведёт себя на сайте

Оно **не грузится**, если: включена экономия трафика, соединение 2G,
включён `prefers-reduced-motion`, или вкладка в фоне. Во всех этих случаях
остаётся постер. Ни одного байта видео не запрашивается до гидратации
страницы — источники добавляются из JS, поэтому ролик не конкурирует за канал
с текстом, шрифтом и первым экраном.

### Альтернатива без правки кода

Ролик можно загрузить прямо в админке: **Настройки сайта → Фон первого
экрана**. Он имеет приоритет над файлами из манифеста. Минус — один файл на все
устройства, без отдельной мобильной версии.

## 3. Фотографии

Все изображения приведены к пропорции того блока, в котором они выводятся. Это
делает скрипт:

```bash
python3 scripts/prepare-home-images.py
```

Он читает файлы из `public/images/home`, кадрирует/вписывает каждый под свой
блок, пережимает и кладёт обратно. Целевые размеры — в `SPECS` внутри скрипта,
там же для каждого кадра написано, почему выбран именно такой режим.

| Файл | Кадр | Режим | Где выводится |
|---|---|---|---|
| `direction-handheld.jpg` | 1200×900 (4:3) | вписать | Направления |
| `direction-stationary.jpg` | 1200×900 (4:3) | вписать | Направления |
| `direction-ew.jpg` | 1200×900 (4:3) | обрезать | Направления |
| `production-wide.jpg` | 1280×720 (16:9) | обрезать | Производство, крупный кадр |
| `production-1…5.jpg` | 900×1200 (3:4) | обрезать | Производство, лента |
| `cta-backdrop.jpg` | 1600×700 | обрезать | Фон финального призыва |

**Два режима, и это не прихоть:**

- **вписать** — для неоновых рендеров на чёрном. Изделие видно целиком, поля
  дозаливаются цветом фона самого файла, поэтому стык не виден. Портретный
  рендер стационарной установки при обрезке лишился бы стволов.
- **обрезать** — для фотографий. Точка внимания задаётся полем `focus_y`
  (у кадра цеха он смещён вверх: интересен ряд стеллажей, а не пол).

### Порядок замены

1. Положить новый файл вместо старого, имя то же.
2. `python3 scripts/prepare-home-images.py`
3. Поправить `alt` в `src/modules/home/lib/media.ts` — он описывает **то, что
   на кадре**, и, пережив смену картинки, начинает врать.
4. Поправить подпись в `content/home-content.ts` (для ленты производства).

> **Скрипт не идемпотентен.** Он перезаписывает файлы на месте. Если исходник
> лежит отдельно, укажите каталог: `--source путь/к/исходникам`. Иначе повторный
> прогон кадрирует уже кадрированное.

### Если картинка не обновилась

Оптимизатор Next кэширует результат по паре «путь + ширина», а браузер держит
ответ в своём кэше. После замены файла с тем же именем:

```bash
rm -rf .next/cache/images
```

и жёсткая перезагрузка в браузере (Cmd/Ctrl + Shift + R). Без этого на экране
останется старая картинка при новом файле на диске — ошибка, которую легко
принять за поломку вёрстки.

### Права на файлы

Файлы в `public` должны быть доступны на чтение тому пользователю, от которого
работает сервер, а каталог — на запись тому, кто выкладывает картинки:

```bash
chmod -R g+w public
```

## 4. Тексты и цифры

Всё — в [`content/home-content.ts`](./content/home-content.ts). Ни один компонент
не содержит зашитых строк.

Временные значения обёрнуты в `TBD(...)` и в режиме разработки **подчёркнуты
жёлтым пунктиром** с подсказкой при наведении. Заменяя значение реальным,
меняйте `TBD(...)` на `REAL(...)` — подчёркивание исчезнет.

Найти всё, что осталось заменить:

```bash
grep -n "TBD(" src/modules/home/content/home-content.ts
```

Что ещё ждёт реальных данных:

- количество выпущенных изделий, регионов поставки, испытательных пусков и год
  основания — строка показателей под первым экраном;
- названия и файлы сертификатов (секция «Доверие»);
- охват поставок по регионам (там же).

Уже заполнено и снято с пометки: рабочая дистанция и площадь раскрытия сети,
площадь производства, годовой выпуск, численность, вся хронология.

## 5. FAQ

Живёт в Payload, коллекция **Контент → FAQ**. Темы содержат вопросы; у каждого
вопроса есть:

- **Ответ** — форматируемый текст (списки, ссылки, выделение);
- **Показывать на главной** — попадёт в блок FAQ на главной (не более пяти);
- **Показывать** — скрыть, не удаляя;
- **Порядок** — меньше значит выше;
- **Якорь** — заполняется сам, даёт прямую ссылку `/faq#...`.

Стартовый набор (3 темы, 13 вопросов) заводится командой:

```bash
pnpm seed:faq
```

Скрипт идемпотентен — повторный запуск обновляет темы, а не дублирует их.
Ответы с пометкой **«[ЗАПОЛНИТЬ]»** нужно заменить реальными данными.

## 6. Шрифт

`PaluiSP2-Bold` лежит в `src/assets/fonts/` (там же лицензия). Подключён через
`next/font/local` в `app/(frontend)/layout.tsx`.

**Важно: гарнитура унициальная** — строчные буквы отображаются глифами
прописных. Поэтому она применяется только через класс `.u-display`, который
принудительно поднимает регистр, и только к коротким надписям: первый экран,
названия направлений, годы хронологии, финальный призыв. Длинный текст ею
набирать нельзя — она очень широкая, и три строки капслоком занимают экран
целиком.

## 7. Структура

```
components/
  HomeHero.tsx        первый экран + лента показателей
  HeroVideo.tsx       логика загрузки видео (клиент)
  SectionIndex.tsx    липкий указатель разделов + полоса прогресса
  ManifestoSection.tsx
  DirectionsSection.tsx
  ProductsShowcase.tsx  два ряда товаров из каталога
  PrincipleSection.tsx  липкая схема перехвата
  AudienceSection.tsx
  ProductionSection.tsx
  TimelineSection.tsx   горизонтальная хронология
  TrustSection.tsx
  FaqSection.tsx
  FinalCta.tsx
  ParallaxFrame.tsx
  primitives.tsx      Section, Container, MediaSlot, Placeholder
content/home-content.ts   ВЕСЬ текст страницы
lib/media.ts              ВСЕ пути к медиа
```

Движение — без анимационных библиотек:
`src/shared/components/motion/Reveal.tsx` (появление) и `useScrollProgress.ts`
(прогресс прокрутки в CSS-переменную `--p`). Сами анимации описаны в
`app/(frontend)/home.css`.
